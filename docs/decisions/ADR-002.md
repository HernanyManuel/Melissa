# ADR-002 — Identidade e isolamento de tenants

Estado: proposta de referência da Phase 0, para revisão no PR.

## Contexto

Tenant arbitrário no browser, worker ou FK é vetor de fuga de dados.

## Decisão

Auth no backend; refresh opaco rotativo; TenantContext validado por membership; RLS + filtros + FKs compostas; bootstrap/identidade globais em repositories restritos.

## Alternativas e consequências

Managed auth continua alternativa futura. Runtime sem BYPASSRLS e sem ownership. Não tratar RLS como proteção contra aplicação inteiramente comprometida.

## Validação

P2: A/B, pool reutilizado, membership revogada, refresh replay, último owner, runtime role real.
