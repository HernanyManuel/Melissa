# ADR-001 — Monorepo e monólito modular

Estado: proposta de referência da Phase 0, para revisão no PR.

## Contexto

Uma base de código precisa servir milhares de empresas sem workflows por cliente.

## Decisão

NestJS modular, API e worker separados no mesmo monorepo; PostgreSQL/Redis; Flutter consome OpenAPI.

## Alternativas e consequências

Microserviços desde início aumentariam coordenação e operações. Manter limites de módulos e outbox permite extração futura. Árvore original preservada; módulos criados incrementalmente.

## Validação

P1: builds independentes de API/worker/Flutter; testes de fronteiras e nenhuma regra nos controllers.
