# ADR-007 — Flutter Web acessível e contratos

Estado: proposta de referência da Phase 0, para revisão no PR.

## Contexto

A app precisa ser intuitiva e manter paridade de regras entre frontend e backend.

## Decisão

Flutter Web, Riverpod/go_router, feature layers, Material 3 personalizado, ARB seis idiomas, cliente OpenAPI e estados assíncronos explícitos.

## Alternativas e consequências

Apps nativas distribuídas depois do MVP; geração de cliente não substitui repositories/validação server-side. Escolhas visuais ajustáveis por tokens.

## Validação

Widget/integration tests, teclado/leitor de ecrã, layouts 360/768/1440, troca de tenant sem estado residual.
